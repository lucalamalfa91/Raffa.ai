## NW-63r — bounding-box overlay + phrase-edit

**Decision.** Four pieces, exactly the ADR-029 pre-decided shape (a–c) plus one
new provenance ruling:
1. Widen the gateway wire + `AiOcrPage` to carry layout geometry.
2. A migration adds per-word geometry columns on the evidence surface.
3. The viewer overlay consumes those columns.
4. The phrase-edit write is a new document endpoint that **never overwrites a
   stored proposal or a human correction** — it appends a differentiable
   override row.

**ADR action:** **amend ADR-017** (widened `words`/`polygon`, `prebuilt-layout`
now called); **amend ADR-003** (geometry columns — the w17 clause-2 refusal is
now discharged); **amend ADR-027** (the re-derive-never-overrides rule already
there, extended to phrase edits). ADR-029 is the governing ADR (no new ADR).

**Consequences.**
- Gateway: `DocumentIntelligenceContracts.cs:24-26` `DocumentIntelligencePage`
  gains a nullable `words` list; each word carries `content`, `span`
  (`offset`/`length`), `polygon` (normalized `x1,y1,x2,y2,x3,y3,x4,y4,`), and
  `confidence`. `AiOcrPage` (`Contracts/AiOcrPage.cs:13`, currently
  `(PageNumber, Text)`) widens to carry `IReadOnlyList<AiWord>` where geometry
  was returned; `FoundryOcrClient.MapPages` (`Foundry/FoundryOcrClient.cs:144`)
  maps words when the analyze result includes them. The `ocr` role switches to
  `prebuilt-layout` (api-version 2024-11-30) — **cloud-architect owns the model
  id / account confirmation**; the gateway role table in ADR-017 is amended, not
  re-opened.
- Schema: one migration in `Raffa.Documents.Contracts`, regenerating
  `documents-contracts.sql` (`dotnet ef migrations script --idempotent`).
  Geometry is **not** on `extraction_evidence` (that table is per field, not per
  word — ADR-003 w17 clause 1). The box overlay needs **word boxes per page per
  document**, which is a new table or a JSONB column scoped to the document's
  page map — **decision: a new tenant table `document_page_word`** (tenant_id,
  document_id, page, word text, polygon, word_index), RLS `ENABLE`+`FORCE`+
  `tenant_isolation` in the same migration (ADR-009, mirroring ADR-003 w16
  clause 2). It is not an `extraction_evidence` concern; it is a derived,
  replace-in-place rendering datum like the preview pages (ADR-029 footer).
  Because a new table derives from `TenantScopedEntity`, the automatic RLS
  check (`TenantRlsMigrationCheckTests.cs:37-44`) covers it — no hand-written
  test owed.
- Viewer: client renders boxes as absolutely-positioned DOM over the PNG
  (ADR-029/ADR-012 — no new runtime dependency). `page` + `word` + `polygon`
  read-back is the cited page's word list.
- Phrase edit: `DocumentsEndpointExtensions.cs` has **no `MapPatch`/`MapPut`**
  today (`:90-96`). New `PATCH /api/documents/{id}/evidence/{field}` is **not**
  the right surface — phrases are word-level, fields are field-level. Ruling:
  the edit is **viewer-scoped**, a new write on the *document* (not the
  contract field): it writes an `ExtractionEvidence`-adjacent **override** row
  keyed by (contract_id, field_name) reusing the existing `CorrectionHistory`
  shape (ADR-003 states it is "the existing correction path"), carrying a
  provenance marker `source = "phrase-edit"` and never mutating the machine's
  proposal `value`/`confidence`. **Proposal and override stay two rows, never
  one merged row** — this is the literal OQ-w18-002 answer and the
  proposal-vs-override rule ADR-027 w17 footer clause 2 already names.

**Assumptions.**
- `prebuilt-layout` is on the same account, no new SKU/role (cloud-architect's
  OQ-w18-005). If a role is owed, it is an NW-40-adjacent find.
- A per-page word list is sufficient; no paragraph/table geometry is needed for
  the box overlay in V1.
- The edit write is tenant-scoped and membership-verified (security seat), and
  read back by re-fetching the evidence list (client seat).

## NW-23 — Portfolio `category` filter

**Decision.** Filter the portfolio by **supplier category**, resolved in the
host (composition root), not by a `Contract` column — `Contract` has only
`ContractDocumentType`. `Supplier.Category` (`Domain/Supplier.cs:36`) is the
legal source, joined exactly like `supplierName` already is
(`PortfolioEndpointExtensions.cs:133-146`, `DependencyDirectionTests.cs:63`
allows `[SharedKernel, AiGateway]` only — so `Raffa.Documents.Contracts`
**cannot** reference `Raffa.Suppliers.Products` directly).

**ADR action:** **amend ADR-002** (host composition, the w17 clause-3 rule
"the 360 composes in the host" applied to portfolio filtering). The stale
`PortfolioFilter.cs:11-17` comment is swept in the same task.

**Consequences.**
- `PortfolioFilter` gains no new member that fetches suppliers; instead a
  `category` query param on `GET /api/contracts` is resolved in
  `PortfolioEndpointExtensions` by joining `supplierName` (already fetched via
  `ISupplierNameLookup`) → `Supplier.Category`. The module boundary is not
  widened (`DependencyDirectionTests` unchanged).
- §6's word "Type" stays `ContractDocumentType` (the doc-type column); the
  category facet is supplier category. Both facets can coexist; the raw item
  asks for "category/Type".
- No migration — `supplier.category` already exists
  (`SupplierConfiguration.cs:32`, `HasMaxLength(200)`).

**Assumption.** OQ-w18-003: filter by supplier category joined in the host; if
the supplier has a null category, the row is absent from that facet (honest,
not "uncategorised" fabricating a fact). po/ux rule the visible vocabulary.

## NW-55 — Ask citation cards

**Decision.** Two corpora, two treatments. **Tenant citations** gain a real
deep-link to the w17 viewer route (`/documents/:id/viewer`) at the cited
page/span — `previewUrl` becomes a real first-page object URL only where a page
exists, else the card becomes a **CTA link**, never the empty placeholder.
**Product (`raffa`) citations** have no page → drop the preview slot and render
a CTA card to the section (already the design intent).

**ADR action:** **amend ADR-024** (citation-card corpus rule) — and the client
half is **ADR-012/ADR-018** (route exists, deep-link lands). No new ADR.

**Consequences.**
- Backend (`software-architect` owns `PackItem.PreviewUrl`, `Raffa.Chat/Application/Pack/PackItem.cs`):
  `PreviewUrl` for a tenant citation becomes a real page-1 blob URL (ADR-029
  route); `Href` for a tenant citation becomes the viewer deep-link with the
  cited page. `Corpus == "raffa"` items carry `Href` (capability route) and
  `PreviewUrl = null` — the client renders a link card, not a preview.
- Client: `CitationCard.tsx:42` drops the `"No page preview available"`
  placeholder entirely — tenant cards render the preview **or** a "Open at page
  N" CTA, never the dead placeholder; raffa cards are pure CTA.
- Contract: `citation` schema already carries `previewUrl`/`href`/`page`
  (`schema.ts:656,674`) — no contract shape change; only the values become real.

**Assumption.** OQ-w18 (deep-link) lands after NW-63r's box is drawn (order
constraint 1) so the box and the cited page render together.

## NW-56 — 360 "Ask about it" briefs that contract

**Decision.** The scoped Ask entry must **brief the contract it came from**, not
land on the generic gate/hello. The `?scope=` handler exists but is empty
(`askViewModel.ts:428-431`); the gate (`ask/index.tsx:94`) runs R-ASK-10
**before** the scope is applied.

**ADR action:** **amend ADR-024** (scoped entry path) + **ADR-012** (route/state
consumption). No new ADR.

**Consequences.**
- The scoped Ask turn and the global Ask turn share the **same engine** but the
  scope is applied **before** the domain gate, so the pack is contract-briefed
  from the first message: the composition root (`AskCopilotService`) seeds the
  scoped context (the originating contract's facts + recent strategy) into the
  pack on entry, and follow-ups are contract-scoped.
- No new endpoint: the `?scope=` query param is already accepted; it must
  resolve to a contract-scoped conversation. The scoped entry carries the
  contract id and Ask does **not** re-run the upload onboarding when a valid
  scope is present.
- Route/state is client-architect's (ADR-012); the server half is the gate
  ordering + pack seeding in `AskCopilotService`.

**Assumption.** A scoped entry with a contract id bypasses the
"no documents yet" onboarding branch (it is scoped-briefed), while the
unscoped global entry keeps the existing gate.

## NW-57 — Quote check: market benchmark

**Decision.** The job-to-be-done is a **market benchmark**, not a manual savings
worksheet. Keep every request; no "send to Home". The gap is first-of-type cold
start + history + benchmark-first UX — the benchmark read already exists
(`IBenchmarkService`, `GET /api/quotes` documented w16 NW-12).

**ADR action:** **amend ADR-024** (market-benchmark quote path) + **amend
ADR-001/ADR-028** (quote job-to-be-done wording) as reconciling footers. No new
ADR; the market source is ADR-024's.

**Consequences.**
- Server: the quote assessment must resolve a market **benchmark band** against
  the same `IBenchmarkService` / `(supplier, product, geography)` key ADR-024
  already uses (one resolution, one answer — the w17 clause-7 rule), and return
  it as **honest representative or explicit insufficient-data**, never a
  fabricated percentile (ADR-024 w17 clause B6).
- No new module: `Raffa.Quotes` reads the `Raffa.Benchmark` port
  (`IBenchmarkService` is allow-listed for `Raffa.Renewals` — confirm the
  same for `Raffa.Quotes`; if not, compose in the host as ADR-002 w17 clause 3).
- History is a read of the existing `GET /api/quotes` list (no new endpoint),
  surfaced by the client.
- Contract: benchmark result shape is an inline nested object (ADR-012 §9: no
  `$ref`, nesting free) — nullable band with `representative`/`insufficient_data`.

**Assumption.** `Raffa.Quotes` may reference `Raffa.Benchmark`'s port
(verify against `DependencyDirectionTests` allow-list at the table); if it may
not, the band is resolved in the host and passed into the quote assessment DTO.
