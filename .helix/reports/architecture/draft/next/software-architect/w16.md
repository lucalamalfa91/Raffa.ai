## NW-21 — quote outcome updates Savings

**⚠ Needs no new column and no migration** (intake §2 gap 1 says it does).
`NegotiationOutcome.cs:127-134`: `SavingsOpportunityId` is "an explicit,
**caller-supplied** fact, never inferred" *because* no derivable link exists.
The intake quoted that comment and read a decision as a defect.

- **Decision**: the outcome **names** an opportunity; the server never resolves
  one. Server path already complete: `NegotiationOutcomeCaptureRequest.cs:55` →
  entity `:173` → `NegotiationsEndpointExtensions.cs:97` →
  `NegotiationOutcomePropagationService.PropagateAsync:111-171` →
  `SavingsOpportunityService.UpdateAsync(realizedAmount: outcome.RealizedSaving)`
  (`:130-136`), which sets `Status = Realized` **and** inserts `RealizedSavings`.
  Only gap: the client never populates a field already on the wire
  (`client.ts:877` types it; `routes/quotes/index.tsx:274-282` omits it).
- **Why not a column**: `savings_opportunity.quote_id` invents the
  quote-originated opportunity `SavingsOpportunity.cs:23-27` calls "R4, out of
  scope", and **nothing would populate it** — opportunities come from a contract
  comparison, before any quote exists. Join not derivable either:
  `Quote.Supplier` is `string?` free text (`Quote.cs:76`) vs
  `SavingsOpportunity.SupplierId` `EntityId?` (`:42`); `Quote` has no `ContractId`.
- **Consequences**: zero backend files, zero migrations, **zero contract delta**.
  Picker source exists — `GET /api/savings` (`SavingsEndpointExtensions.cs:36`),
  membership-guarded (`:61`). This is a **client task + acceptance walk**; do not
  size it as schema work.
- **OQ-w16-005**: status only. `SavingsKpiCalculator.cs:89-107` sums
  `EstimatedSavingsLow/High` in **every** bucket including `Realized`; an amount
  move needs `SavingsOpportunitySnapshot` to carry the realized value plus a
  fourth summation rule — my lane to build, ADR-001 call to make. Recommend W17.

## NW-11 — renewal actions have an HTTP read-back

- **Decision**: `GET /api/renewals/{contractId}/action` (200/404) mirrors the
  POST and serves Contract 360; **plus** the persisted row embedded in each
  `GET /api/renewals` row — Renewals and Savings are *list* surfaces, so one GET
  per row is an N+1 across the portfolio.
- **Field-name hazard (binding)**: `GET /api/renewals` already returns `action`
  (`RenewalsEndpointExtensions.cs:239`) = the **computed `RecommendedAction`**,
  not the persisted row. Embed under a different name — proposed
  `savedAction: {owner, status, action, updatedAt} | null`. Reusing `action`
  overwrites a deterministic calculator's output with user state on a live surface.
- **Consequences**: service exists and is tenant-scoped —
  `RenewalActionService.GetActionAsync:158-171`, zero production callers, comment
  `:150-157` anticipating exactly this. No migration: `renewal_action` has unique
  `(tenant_id, contract_id)` + RLS (`20260904223135_…:42,52-54`). Contract: 2
  deltas. Single writer on `RenewalsEndpointExtensions.cs`; NW-32 also edits
  `RenewalActionService.cs`, so theme A precedes (§5 constraint 1).
- **Assumption**: `{id}` on the POST is the **contract** id (service keys on
  `ContractId`); task confirms at handler `:353`.

## NW-13 — Contract 360 step ticks are server state

- **Decision (OQ-w16-006)**: `Raffa.Documents.Contracts` owns the ticks as a
  **contract child resource** — `GET`/`PUT /api/contracts/{id}/negotiation-steps`,
  mirroring `GET /api/contracts/{id}/corrections`
  (`ContractsEndpointExtensions.cs:66`, handler `:431-470`: `ResolveTenantAsync`
  first, GUID→400, null→404). `Raffa.Renewals` **cannot** own it — ADR-002
  allow-list `[SharedKernel, Benchmark]` (`RenewalActionService.cs:23`).
- **Keyed by named step, never index.** The client stores a positional
  `boolean[4]` (`negotiationStepsStore.ts:11,18,24,31`) holding **no step names**;
  two of four labels are parameterized (`contract360ViewModel.ts:211-218`). Stable
  key = the four named ordered steps of `screens-v2.md:106-108` (*Notify · Request
  revised pricing · Counter with the market benchmark · Sign or send non-renewal
  notice*), stored as a **closed enum by name** — the convention
  `NegotiationOutcome.LeversUsed:112-116` already uses ("enum(-list) as string",
  never a native array). An index key silently re-points every tick the day a step
  is inserted.
- **Consequences**: one new tenant table `contract_negotiation_step`, unique
  `(tenant_id, contract_id, step)`, **RLS policy in the same migration as the
  table** (ADR-009; ADR-003's w14 rule for `workspace_invitation`). One
  regenerated `Raffa.Documents.Contracts/Migrations/Scripts/documents-contracts.sql`.
  **No CI YAML moves** — verified: `backend.yml:277-285` and `:309-317` already
  list that module. Contract: 2 paths. Files: `ContractsEndpointExtensions.cs`
  (single writer), new service, entity + configuration + migration.
- **PUT, not PATCH**: the client holds all four ticks and writes the set
  (`index.tsx:274`); a whole-set PUT is idempotent, needing no merge semantics.
- **product-owner**: canonical steps? per-contract or per-renewal-cycle? I assume
  **per-contract** (the store keys on contract id alone); per-cycle adds a cycle
  key to the unique constraint — cheap now, a migration later.

## NW-31 — dual role headers retired

**⚠ ADR-027 `:198` does not license an unauthenticated re-enqueue.** OQ-w16-004
reads it as needing "**no new identity**, no secret and no Terraform". `:198`
describes the **handler** ("same handler, same replace step") reached by
`POST /api/documents/{id}/reprocess`. The same ADR names the driver at `:719` —
"**an admin inside that tenant** can drive it without any cross-tenant read" —
and `:720-723` rules that closing the residual needs "the cross-tenant sweep
ADR-009 forbids". **No worker-side path re-enqueues without an authenticated
tenant-scoped caller, and a worker-side sweeper is forbidden outright.** So:

1. **Token-bearing identity** → identity plane + Terraform → **cloud-architect's
   seat activates**, infra phase first.
2. **Publish to the topic directly** with the existing Azure login → still
   Terraform (Data Sender role), and a CI identity could mint extraction messages
   for any tenant, bypassing API authz. **I reject this.**
3. **Retire the workflow**; a tenant Admin drives reprocess through the API —
   ADR-027 `:719`'s own model. Zero infra, zero identity, and it deletes
   **already-dead** code: the workflow 401s at its first API call (`:203-206` →
   `CallerContext.cs:116-120`) and `:208-211` turns that into `exit 1`, making its
   403 diagnostic at `:274` unreachable.

**I recommend 3**, with 1 as fallback if delivery-manager needs the bulk operator
capability. Either way **"cloud delta is zero because ADR-027 says so" does not
hold** — it is zero only under option 3. File disposition is delivery-manager's
(ADR-016 w15 clause 21); I correct the ADR-027 reading it rests on.

- **Capabilities half — drop the server-side role gate, do not re-home it.**
  `/api/capabilities` is deliberately anonymous and tenant-agnostic
  (`CapabilitiesEndpointExtensions.cs:62` takes only `HttpRequest`; `:47-48` "not
  sensitive, tenant data"), and the client sends a bearer but **no `X-Tenant-Id`**
  (`client.ts:2760-2765`). Membership-gating makes `ResolveTenantAsync` return
  **400 on every call** until the client changes — on a route the shell renders on
  every screen (`GlobalAskBar.tsx:43`, `ask/index.tsx:169`). The response already
  carries `roleGate: "any" | "admin"` per row (`schema.ts:629`), and ADR-012's w14
  footer makes the client's role **server-derived, presentation-only,
  least-privilege by default**. Server returns the whole catalog; the client
  filters. `X-Role` goes with no replacement and no new coupling.
  - *Rejected*: tenant-scope + `IsAdminAsync` — accurate, but buys a tenant
    coupling and a 400 window for a non-sensitive list. **Security-architect
    confirms or overrules**: visibility gate, not authorization gate.
- **Consequences**: delete `RoleHeaderName` (`:54`) and `CallerIsAdmin` (`:77-80`);
  contract drops the `X-Role` parameter (`raffa-api.v1.json:5239`, description
  `:5236`) and the stale `X-Workspace-Role` sentence on `deleteDocument` (`:1227`,
  inherited by `reprocessDocument` `:1310`). Five test files assert the headers
  confer nothing — **rewritten, not deleted**. Folded in: the dead
  `TenantHeaderName` (`DocumentsEndpointExtensions.cs:80`, zero usages) and the
  stale doc comments, which are what make a grep-based audit re-report a false
  verdict.

## NW-32 — every write names its actor

- **Decision — signature shape**: a **required positional `string` after the
  entity id**, as the three already-correct document paths do it:
  `ReprocessAsync(tenantId, id, caller.Identity!, ct)`
  (`DocumentsEndpointExtensions.cs:512`; likewise `:147`, `:576`). No new type, no
  ambient accessor — an ambient actor lets the caller-less sites compile and
  silently write nothing.
- **⚠ The replacement is not always a user, and the codebase already says so.**
  OQ-w16-007 asks what the two caller-less sites do. Live convention: **named
  system actors** — `NegotiationOutcomePropagationService.cs:97`
  (`SystemActor = "system:negotiation-outcome-propagation"`) and
  `QuoteExtractionPipeline.SystemActor`. Caller-less writes take
  `system:<process>`, never a default and never `"unattributed"`. This makes
  A16-4's "grep returns nothing" reachable **without inventing anything** and
  keeps ADR-011 meaningful: "nobody" becomes "this process".
- **Consequences**: 9 service types across 5 modules change signature — a
  cross-module edit, and the single-writer reason **theme A precedes theme B**
  (same five services NW-11/12/21 modify, §5 constraint 1). 10 `UnattributedActor`
  declarations go, one already dead (`DocumentsEndpointExtensions.cs:81`).
  `RagAnswerServiceTests.cs:70` asserts the literal and is **rewritten to assert
  the resolved actor**, never deleted.
- **Sizing**: a **falsified audit trail**, not an auth bypass — every route
  reaching these services already 401s first. ADR-011 violation, no data-loss
  class, so `should` stands.

## NW-07 — conversation `user_id` is the token subject

**⚠ The fix is not "one rule for comparing `ExternalSubjectId`".** Intake gap 2
pairs `WorkspaceDirectoryService.cs:104,144` against `CallerContext.cs:143` and
asks for one rule. The predicate is `u.Email.ToLower() == normalizedIdentity ||
u.ExternalSubjectId == normalizedIdentity` — **one lower-cased input driving two
comparisons**. The `Email` half is **correct and must stay** (emails are
case-insensitive; `:96-99` says it deliberately matches the `identity_self` RLS
policy's `lower(email)`). Only the `ExternalSubjectId` half is wrong, `oid` being
opaque and case-sensitive (`CallerIdentity.cs:60-68,80-81`).

- **Decision**: compare `ExternalSubjectId` against the **trimmed, not
  lower-cased** identity; leave `Email.ToLower()` alone. Two comparisons, two
  rules, one deliberate reason each. A blanket "remove the lower-casing" breaks
  discovery matching **and** diverges from a live RLS policy.
- **For security-architect (not mine)**: the identity GUC is trim+lower (`:96-99`)
  and `identity_self` compares `lower(email)`. If the identity is now an `oid`,
  can that policy match at all? I have not proven either branch; it is one `Grep`
  of ADR-009's policy DDL and it is your lane.
- **Orphaned rows (OQ-w16-001)**: **no backfill**. Mapping a pre-w15 email key to
  an `oid` needs a directory lookup with no batch path; `Raffa.Chat/Migrations/`
  holds only `Initial` + the RLS policy. **Recorded in the ADR-024 footer, not
  executed** — provably intentional, not silently orphaned.
- **A16-1 is vacuous** (`oid` is invariant under UPN casing); product-owner
  ratifies the rewording.
- **Consequences**: one predicate change; delete the stale doc paragraph
  (`ConversationsEndpointExtensions.cs:23-37`, still asserting a 400 and an
  `X-User-Id` fallback that no longer exist); one ADR-024 footer. No migration.
