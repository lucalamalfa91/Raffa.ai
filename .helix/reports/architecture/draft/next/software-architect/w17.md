## NW-73 — Bulk whole-tenant reprocess console

- New console **`Raffa.Tools`** under `/src/` in `Raffa.slnx` (XML `<Solution>`,
  17 src projects, `:3-19` — a `*.sln` glob finds nothing). A **second
  composition root**: no business rule, no table, not referenced by API/Worker.
- Calls `DocumentReprocessService.ReprocessAsync` (`:62`) per document, nothing
  else. Re-implementing `RequeueClassificationJobAsync` (`:138-176`) is
  forbidden: the `ClaimedAt = null` reset (`:168`) is what lets the Worker's
  `claimed_at IS NULL` claim re-deliver, and `AttemptCount` is deliberately kept
  (`:135-136`) — a psql equivalent silently drops both.
- It composes **seven** dependencies (`:37-44`) by reusing the modules' own
  `ServiceCollectionExtensions`, never hand-building them; so it references
  `Raffa.Messaging` + `Raffa.Storage`.
- **⚠ security seat — the Admin gate does not travel with the service.** `:30-31`
  states it "does not know about roles: the endpoint enforces Admin before
  calling"; a console bypasses `DocumentsEndpointExtensions.cs:506-509` entirely.
  Its only authorization is the principal's Azure RBAC + the Postgres credential.
  RLS still holds — `ReprocessAsync` opens its own tenant scope (`:67`).
- Actor is required non-blank (`:65`) → `system:bulk-reprocess` (ADR-011 w16
  clause 16); tenant id is an explicit input, never inferred.
- **Throughput**: each call does a blob load (`:88`), chunk delete (`:99-101`),
  publish (`:110`), save, audit write. Bounded concurrency + continue-on-error;
  the Worker's queue absorbs the work. Re-runs are safe — `MessageId` already
  collapses duplicates (`ServiceBusExtractionQueuePublisher.cs:50`).

## NW-71 — Auto-accept a field at ≥ 90 % (server + web)

- **Server decides and persists; web renders.** Raw `confidence >= 0.90` on the
  stored double, **no rounding** (OQ-w17-002). The stash's rounded compare is
  presentation-only for the label — as *the decision* it makes `0.895` accept on
  screen and review in the audit row.
- **One policy type** `ExtractionConfidencePolicy` in
  `Raffa.Documents.Contracts`, consumed by **both**
  `StagedExtractionService.DetermineDocumentStatus` (`:863`, applied `:236`) and
  `DocumentQueryService.IsWeak` (`:46-52`). Today these are duplicated pairs
  (`StagedExtractionService.cs:78,88` vs `DocumentQueryService.cs:33,42`) and
  changing one desyncs the badge from `needs_review`.
  `StagedExtractionService.cs:76-77` already calls its bar "a config knob, not a
  hard-coded business rule" — this discharges it.
- **The per-field decision lands on `extraction_evidence`, not a new table**:
  already one row per (contract, field) carrying `Confidence`
  (`ExtractionEvidence.cs:38,48`), explicitly the extraction-time sibling of
  `CorrectionHistory` (`:14-19`). New nullable `decision` (text `auto_accepted` |
  `review_required`) + `decided_at`; **no SQL enum** — `FieldName` is deliberately
  not an enum (`:36-37`) and this follows it.
- **An auto-accept never overrides a human correction**: reprocess re-derives
  decisions, so it must not silently re-auto-accept a field a human corrected.
- **Scope fence** (OQ-w17-003): `DocumentAdmissionOptions:33` (admission),
  `Raffa.Quotes`' bar, `SavingsProvenanceClassifier.cs:37,46` are different
  decisions, out of scope. `CriticalityScoreCalculator.cs:35` is out of scope for
  retirement but collides with NW-62 (OQ-w17-sa-01).
- **Contract**: per-field `decision` + `decidedAt`, and the threshold exposed
  once, so the web never hardcodes 90 and legend copy is server-fed.
- Audit: one row per document naming **fields, never values**; actor and action
  name are the security seat's.

## NW-22 — Renewal insight `MarketPosition` stays null

**This corrects the intake's framing ("inject and wire").**

- **Do not inject `IBenchmarkService` into `RenewalPipelineBuilder`.** That class
  is contractually *pure and synchronous — no database call, no HTTP call, no LLM
  call* (`:9-11`), while `IBenchmarkService` is async and adapter-backed
  (`MarketFeedBenchmarkAdapter.cs:98-102` reads `market_record`). Injecting it
  breaks a stated purity contract to save one parameter.
- The **host** (`RenewalsEndpointExtensions`) resolves the benchmark per
  candidate and passes it **into** the builder on `RenewalDashboardCandidate` —
  the DTO that exists precisely so the builder never sees a real `Contract`
  (`:16-20`). Same `ToCandidate`/`ComputePriority` pattern, same reason
  (`InsightsEndpointExtensions.cs:33-36`).
- The builder then fills `MarketPosition` (and `AnnualUpliftPercent` where the
  band supports it) instead of the hardcoded nulls `:91-92`, and sweeps `:89-90`.
  `PotentialSavingsRange` stays null unless the band yields one — an honest null
  is not a defect (Appendix C rule 10).

  `prebuilt-layout` + a widened wire contract (`words`/`polygon`) and a widened
  `AiOcrPage` (`:13` carries page + text only); (b) geometry columns on the
  evidence tables (zero `bbox|bounding|polygon` in any `*.sql`); (c) the
  phrase-edit write path.
- **No phrase-edit endpoint this wave**: there is no `MapPatch`/`MapPut` on
  documents at all (`DocumentsEndpointExtensions.cs:90-96`) and the existing
  correction path is field-name → scalar. Editing an OCR *phrase* is a different
  provenance question (does it rewrite extracted text, the evidence, or both?);
  improvising it blurs the proposal-vs-override distinction
  `ExtractionEvidence.cs:14-19` exists to keep. Its own decision, in W18.
- If the council rejects the split it must cut two `should` items and say which
  (§5) — I do not get to cut them silently.
