## NW-63r — bounding-box overlay + phrase-edit (remainder)

**Client decision.** The w17 viewer already renders the PNG page over an
authenticated object URL and revokes it in a `useEffect` cleanup (ADR-012 w17
clause 33). The W18 remainder draws the bounding-box overlay as
**absolutely-positioned DOM over the `<img>`**, consuming the widened
`words`/`polygon` geometry software-architect lands. The overlay is a `<div>`
per phrase box, positioned by page-normalised coordinates the server returns —
**not** a canvas draw and **not** a new dependency: `web/package.json` keeps
exactly five runtime deps (ADR-012 w17 clause 32's fence is untouched).

Phrase-edit on the client is a **write that does not blur proposal vs
override**: the viewer offers an edit affordance that sends the
software-architect-ruled write path (OQ-w18-002 — this seat does not pick
text-vs-evidence; it consumes the ruled contract). The client renders the
server's **persisted** decision back, never a local optimistic override that
survives reload (ADR-012 w14 clause 1: no client store standing in for a
missing GET; a phrase-edit that lives only in `useState` is exactly that
defect).

**Single-writer.** `client.ts` and `web/openapi/raffa-api.v1.json` are the
contended files; NW-63r's contract edit (widened geometry on the evidence/OCR
read model) is one owner per phase (ADR-012 w14 clause 3 constraint 1). The
viewer route file is already owned by w17 and gains the overlay in the same
task.

**ADR action.** `amend ADR-012` (add the overlay-is-DOM rule and the
phrase-edit read-back rule); `amend ADR-018` (viewer already has its route —
clause 9 — no new route; the overlay is a *state* of that route, not a new
one). ADR-029 governs the split; I amend only ADR-012/018.

**Consequences for decomposition.** One web task: viewer overlay + edit
surface, contract regenerated after software-architect's geometry land
(endpoint-one-phase-early per ADR-029 w17 pattern). e2e: a `v2.spec.ts` case
that a cited phrase shows a box and, after edit, the box/overlay re-reads the
persisted value on a second browser (acceptance N17r).

**Open question → assumption.** OQ-w18-002 (does edit rewrite text, evidence,
or both?) is software-architect's wire decision; my assumption is the client
consumes a read-back field and never invents a durable local value.

## NW-55 — Ask citation cards (preview vs section link)

**Client decision.** `CitationCard.tsx:42` still renders the honest
"No page preview available" placeholder for `previewUrl === null`.
`previewUrl` is almost never set (`schema.ts:656,674` type it nullable). Two
corpora, two treatments:

- **Tenant citation** (`documentId` set): the card's `onOpen` deep-links to
  the **viewer route** `/documents/:documentId/viewer?page=<n>&clause=<id>`
  (ADR-018 w17 clause 9), the same citation-landing convention the product
  already uses. No page image fetch is forced into the card; the *link* is
  the treatment.
- **Product citation** (no page, `corpus` = market/calc): a **CTA card** —
  the corpus badge + title + an in-app action, never a fake preview.

The card must not render a preview when it cannot (honest placeholder stays
for the no-URL case), and must not invent a `previewUrl` (ADR-012 clause 1).

**ADR action.** `amend ADR-012` (the citation `onOpen` target for a tenant
citation is the viewer route; product citations are CTA cards, never faked
previews); ADR-018 route already exists (clause 9), so `none` there; ADR-024
owns the reply contract, untouched by me.

**Consequences.** One web task in `web/src/routes/ask/reply/` +
`askViewModel.ts#resolveCitationOpenAction`. software-architect supplies
`PackItem.PreviewUrl`/`DocumentId` so the client never derives it. e2e: N10.

## NW-59 — Ask never dead-ends (abstain recovery)

**Client decision.** `ReplyBody.tsx:75` renders abstain as `.abstain-block`
only; `replyTypes.ts:50` says "abstain/error never carry actions". R-ASK-07
forbade the block as the *only* UX. The abstain reply gains a **recovery
action that unblocks *this* failure** — the action that corresponds to the
specific abstain cause (e.g. "Go to Documents" for no-evidence-in-flight,
"Upload a contract" for empty). It is **one action** (the "one CTA" rule),
server-selected from the closed `actions[]` already on the wire — never a
client-invented affordance (ADR-012 clause 4: the client selects the
sentence, never supplies it).

**ADR action.** `amend ADR-012` (abstain carries a server-selected recovery
action; the client renders at most one, keyed to the cause); ADR-024/020 own
the reply copy/vocabulary — reconciled, not re-authored.

**Consequences.** One web task in `ReplyBody.tsx` + `replyTypes.ts`. e2e: N13.
