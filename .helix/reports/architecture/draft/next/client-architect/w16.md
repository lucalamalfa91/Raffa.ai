## NW-08 — `GET /api/audit`

**C1 — the contract edit has a prose half, and without it the file contradicts
itself.** `raffa-api.v1.json:6` (`info.description`) names **`GET /api/audit`** by
hand in its list of backend routes "that this task deliberately did NOT add here".
Adding the path while leaving that sentence produces a contract that documents a
route and denies documenting it — the exact stale-record class NW-31 exists to
delete. **Both halves are one edit.**

**C2 — the contract gains the path; `client.ts` gains no method and the SPA gains no
route.** OQ-w16-003's assumption (no web audit surface) is adopted. The generated type
arrives for free (`schema.ts` is regenerated wholesale), but an exported `ApiClient`
method with zero call sites is dead code `tsc` cannot flag, and it would need a row in
the w15 surface test (ADR-012 §12). **The convention is on disk, not invented**:
`GET /api/insights/criticality` and `GET /api/contracts/{id}/strategy` are documented
"for completeness, **no `client.ts` wrapper**" (`raffa-api.v1.json:6`). `/api/audit`
joins that set until a screen exists.

- **Consequences**: contract + `schema.ts` only. **`navItems.ts` gains no rail
  entry**; `App.tsx:221-237` gains no route; ADR-018/ADR-020 untouched. A16-2's ladder
  (200/403/404/401) is proven by `curl` and backend tests — **no e2e, no vitest** from
  this seat.
- **If product-owner overrules OQ-w16-003** the cost is a route, a rail entry, a
  method, its surface-test row, a loading and an error state (ADR-018 `:117`) and
  ux-ui-designer seated — a wave item belonging to W17, not a task addendum.
- **ADR action**: amend **ADR-012** (§21 below). ADR-018 **none**.

## NW-31 — the role headers, client half

**C3 — the client half is contract-only.** `web/src` sends neither header
(`client.ts:76` attaches `Authorization` and nothing else; ADR-012 w15 clause 1
re-verified zero `X-Role|X-Workspace-Role` matches, still zero on `f0b3436`). Three
contract sites: the `X-Role` **parameter** `:5239` and its description `:5236`, and
the stale `X-Workspace-Role` sentence on `deleteDocument`'s description `:1227`,
which `reprocessDocument:1310` inherits by reference.

**C4 — this edit is invisible to every check the build runs, so its gate is a
grep.** The generator parses **only `responses`** (`generate-api-client.mjs:132-146`;
ADR-012 clause 3, re-affirmed §9). A `parameters` entry therefore **never reaches
`schema.ts`** — deleting `X-Role` changes no generated byte, fails no `tsc --noEmit`
and fails no build. This is **§10's eighth-site hazard reached from the other end**,
and §10's ruling applies unchanged: *the task's check is a grep of the contract, not
a green build.*

- **Consequences**: no `client.ts` change, no route change, no store change.
  Server-side the Admin catalog rows now come from membership, which is observable
  at `/ask` — the existing e2e case **`v2.spec.ts:648` (A8, "cosa sai fare?" answers
  from the capability catalog, with links that work)** is the one that would catch a
  regression. It needs no edit; it is named so the acceptance walk runs it.
- **ADR action**: amend **ADR-012** (§21); ADR-022's client half is discharged by
  C3 — the footer is the security seat's to write.

## NW-11 — renewal actions read back over HTTP

**C5 — `renewalActionStore.ts` is deleted outright**, not demoted. It is clause 1's
case in its purest form and says so itself (`:8-19`: "there is no way to read it back
over HTTP yet"). Its row joins ADR-012 §1's disposition table:
`raffa.renewals.actions` · `sessionStorage` · stood in for a missing
`GET`-of-the-action · **deleted (NW-11)**.

**C6 — the blast radius is seven source files and six test files, not the three
surfaces the item names.** Src: `renewals/index.tsx:8`,
`renewals/renewalPipelineViewModel.ts:4`, `renewals/InsightCard.tsx:10`,
`contracts/contract360/index.tsx:6`, `contracts/contract360/AnswersBand.tsx:2`,
`savings/index.tsx:5`, `savings/savingsViewModel.ts:2`. Four of the seven import only
the **type** `TrackedRenewalAction`; it is replaced by the generated row type
re-exported from `client.ts` — **no hand-written DTO** (`ADR-012:53`), the shape
`quoteOutcomeStore.ts:1` already uses for `NegotiationOutcomeBody`.

**C7 — the Savings table floods, and a naive store→GET swap ships that.**
`buildOpportunityRows` (`savingsViewModel.ts:236-245`) **prepends every tracked
action** as a pseudo-opportunity row with `estimate: NOT_YET_AVAILABLE` (`:223`).
Today that set is *this session's* actions — a handful. Read back from the server it
becomes **every renewal action in the tenant, permanently**: the opportunities table
fills with rows that are not opportunities and carry no estimate. The row's own comment
concedes the premise (`:210-214`). **Decision: the pseudo-row is retired** —
`buildTrackedOpportunityRow` goes and Savings renders **only real `SavingsOpportunity`
rows** — because NW-21 supplies the real link it was standing in for. Product-visible:
**OQ-w16-ca-01**; assumption in force, retired.

**C8 — "Undo" changes meaning the moment the read-back lands, and silently.**
`handleUndo` (`contract360/index.tsx:261-269`) posts `NotStarted`/"Open" **and**
calls `forgetRenewalAction`. The server row is an **upsert** on
`(tenant_id, contract_id)` (`RenewalActionConfiguration.cs:41`), so it **survives**
the undo — today only the local forget hides it. After the read-back the row returns
as `NotStarted` and Undo will look broken. **Rule: absence of an action is the status
`NotStarted`, not a missing row** — every surface renders `NotStarted` as "no action
taken". `forgetRenewalAction` dies with the store and **no DELETE endpoint is
requested**.

**C9 — no new server field for `supplierId`/`annualSpend`.** The store carries them
"so Savings has it without a second fetch" (`:32-35`); the `renewal_action` row has
neither. The client already joins for both: Contract 360 does it at
`contract360/index.tsx:250` (`pipelineItem?.annualSpend ?? header.annualSpend`) and
Renewals holds `fetchState.items` at `index.tsx:104`. Recorded so the software seat
does not widen a row to feed a fetch the client has already made.

**Shape preference (software-architect owns ADR-026).** Merge the persisted action
into the existing `GET /api/renewals` rows — that closes Renewals and Savings with
**zero new calls** — plus a per-contract read for Contract 360, which does not fetch
that list. **Hard constraint: the new field may not be named `action`.**
`GET /api/renewals` already has `action` at `raffa-api.v1.json:3322`-adjacent
(`:239` of the handler) and it is the *computed* `RecommendedAction`; reusing the name
would silently change the meaning of a field a shipped screen renders.

- **Checks**: vitest over the three view models reading a server row (delivered, CI
  runs `npm test`); one new **`v2.spec.ts`** case — post an action → reload → the same
  action on Renewals, Contract 360 and Savings — which per ADR-012 §12 is **acceptance-
  runbook evidence, not a CI gate**, because no workflow runs Playwright.
- **ADR action**: amend **ADR-012** (§1 table + §21).

## NW-12 — quote and negotiation-outcome read-back

**C10 — deleting the store is nearly free; rendering the outcome is the whole item.**
`quoteOutcomeStore.ts`'s read half is **dead in production** — `loadNegotiationOutcomes`
and `sumRealizedSavings` have zero `src` callers (`quotes/index.tsx:30` imports only
`rememberNegotiationOutcome`; sole call `:290`). So the deletion removes one call site
and one test file. What is genuinely new is that **no surface renders a recorded
outcome at all today**, which is why product-owner is seated.

**Decision — the minimum read-back that closes A16-6 without pre-empting NW-57
(W18).** On `/quotes/:id` the recorded outcome for **that quote** is **fetched on
mount** instead of existing only as the POST's response in local state
(`quotes/index.tsx:289`). No new route, no list screen, no history UI.
**Shape preference**: carry the recorded outcome on the **existing**
`GET /api/quotes/{id}/assessment` (`raffa-api.v1.json:3587`), which the screen already
calls on mount — zero new client calls and zero new `ApiClient` methods. A
tenant-wide outcome **list** may be published in the contract, but under **C2** it gets
no `client.ts` wrapper until NW-57 builds its screen.

- **Checks**: vitest — the quote screen renders a server-supplied outcome with no
  session write; e2e reload case appended to the NW-11 spec.
- **ADR action**: amend **ADR-012** (§1 table + §21).

## NW-13 — negotiation-step ticks

**C11 — the wire is keyed by the four named steps, never by array index.** The store
is a positional, unnamed `boolean[4]` (`negotiationStepsStore.ts:11,18,24,31`); the
labels live in `contract360ViewModel.ts:211-218` and **two of the four are
parameterized** (supplier name, cancellation deadline). A server shape keyed by index
is brittle by construction. The keys are the four **named** steps of
`screens-v2.md:106-108`. Client rules: an **unknown key from the server is ignored**,
never rendered as a fifth tick; a **missing key is unticked**;
`NEGOTIATION_STEP_COUNT = 4` stops being a client constant that shapes the wire.

**C12 — optimistic ticks revert on failure.** `handleToggleStep`
(`contract360/index.tsx:271-276`) is a pure local toggle today. It becomes write +
read-back: tick optimistically, and on failure **revert the tick** and show ADR-018
`:117`'s error state. A tick the server rejected must never survive on screen — that
is the fabricated-fact class. One importer (`index.tsx:20`) and one presentation
consumer (`AnswersBand.tsx:10-11,104-112`); the cheapest of the three retirements.

**Ask**: Undo is **two writes on one gesture** (reset the action, clear the ticks —
`index.tsx:264-265`). Preference: the server clears the ticks as part of resetting the
action, so the client issues **one** call and has no partial-failure state to invent.
software-architect rules (**OQ-w16-ca-02**).

- **ADR action**: amend **ADR-012** (§1 table + §21). **No route change** —
  `/contracts/:id` is unchanged.

## NW-21 — quote outcome updates Savings

**C13 — the client never resolves the link, and therefore sends nothing new.** There
is no derivable link (`NegotiationOutcome.cs:127-131`), so a client that matched an
outcome to an opportunity on `contractId`/`supplierId` would be **inferring a server
fact** — prohibited by ADR-012's w15 clause 4 and §13.2. Two lawful shapes: the server
resolves it at the `Raffa.Api` composition point, or the user picks from a
server-supplied candidate list. **Preference: server-side resolution**, under which
`quotes/index.tsx:274-282` is **unchanged** and NW-21's client cost is **zero** — the
status move is observed through NW-11/C7's Savings table.

**Roster consequence if the table rules otherwise**: a user-picked link is a **new
control and a new empty state** on the quote screen, which seats **ux-ui-designer** —
a seat §3 currently marks uninvolved. Flagged before, not after (**OQ-w16-ca-03**).

- **ADR action**: **none from this seat** — `client.ts:877` already types the field;
  the column, migration and composition are software-architect's.
