## 0. Two cross-cutting rulings (bind NW-71/65/66/64/63 — decide once)

**R1 — one vocabulary, three values, and `.tag-accent` leaves confidence.**
A fact is *officialized* when the server says so. `officialized` is an ADR word
and **never appears on screen**. On screen, keyed on the server's per-field
decision (NW-71's `pending` / `auto_accepted` / `human`):

| Server decision | Variant | Label |
|---|---|---|
| `auto_accepted` | `.tag-neutral` | `Accepted automatically · NN%` |
| `human` | `.tag-neutral` | `Accepted by you` (no %: a human decision has no confidence) |
| `pending` | `.tag-outline` | `Review · NN%` |

Consequence the council must record: **`.tag-accent` is released from
confidence entirely** and stays reserved for `failed`, High risk and `Invited`.
Today it means "Flagged · NN%" on four surfaces (`WhyClauses.tsx:56`,
`FactTable.tsx:35`, `contract360ViewModel.ts:574`, `reviewViewModel.ts:282`).
Retiring the middle band is the whole point of one threshold.

`auto_accepted` and `human` must stay **visually distinct**. Painting them
alike hides exactly the defect client-architect found (`useReviewSession.ts:177-182`
writes + reads back, `:184` is React state with no network) — three
durabilities, one paint. Distinct labels make the read-back testable.

**R2 — display floors, never rounds.** `semantics.ts:33` uses `Math.round`,
which is what creates OQ-w17-002's contradiction: a pending field at `0.895`
would read `Review · 90%` — the screen printing the threshold number next to
the word that denies it. Rule: **every displayed confidence is `Math.floor`**.
`0.895 → 89%`, `0.90 → 90%`, `0.999 → 99%`. A number is never rounded up to a
value the fact does not hold, and label and figure can never disagree at the
boundary. This is presentation only; the decision stays the server's.

## 5. NW-63 — viewer chrome (`must`, split per OQ-w17-001)
