## NW-63r — bounding-box overlay + phrase-edit (remainder)

ADR-020 w17 §16 fixed the viewer chrome, four states and the binding copy rule
(*"Page N — the wording is highlighted below"*, must not promise a box). NW-63r
retires that restriction. Two decisions now payable:

1. **Overlay.** Page canvas (`--color-surface`, 2px left rule) gains a **drawn
box on the cited phrase** when `?clause=` is present. It is a tint —
`--color-accent-100/200` (`design-system.md:25`), zero radius, 2px accent stroke
— reusing the highlight idiom `ClauseHighlight.tsx:28-36`, **not a new
component**. No clause → bare image + page-nav (ADR-020 §16), box-free.
2. **Phrase-edit is Review-only, never draw→edit on the viewer.** The viewer
*shows* the box; *correcting* returns through Review's `PATCH
/api/contracts/{id}` field→scalar (`ExtractionEvidence.cs:14-19`) and ADR-020
w17 §13(d)'s "Not found in the document" section. A second write path on the
viewer is the class the single-writer constraint exists to prevent. The
corrected value renders as *your correction*, never re-badged with confidence
(ADR-019 w17 cl 7: `human_accepted` has no percentage). OQ-w18-002 provenance
is sw's; my copy works whichever lands.

**Anchors.** `ClauseHighlight.tsx:28-36`; `--color-accent-100/200`
(`design-system.md:25`); ADR-020 §13(d)/§16; `ExtractionEvidence.cs:14-19`.

**Divergence.** `screens-v2.md` has no viewer (recorded ADR-020 §17);
requirements win.

**ADR action.** `amend ADR-020` (new §27). `ADR-019 none`.

## NW-23 — Portfolio category filter

**Vocabulary ruling (mine) + control.** §6's word is **Type**. `Contract` has
only `ContractDocumentType`; `Supplier.Category` exists. The filter is labelled
**"Type"** regardless of which join sw rules (OQ-w18-003): if the host join on
`Supplier.Category` is the target, the **label stays "Type"** and the **values**
are the joined categories; the vocabulary never renames Type→Category. If no
join is legal, **no control ships** — "V1 still cannot" (an empty filter is a
lie). Product-owner owns "Type enough?"; join mechanics are sw's.

**Control:** a single `.seg` (the idiom `AttentionFilter.tsx:25` already uses)
above `PortfolioTable.tsx`, filtering client-side over the already-fetched page
(the screen already filters client-side — `portfolioViewModel.ts`). No
type-ahead, no multi-select.

**Anchors.** `PortfolioTable.tsx:45-71`; `portfolioViewModel.ts:59-84`
(`buildPortfolioRows`); `screens-v2.md:114-121`.

**ADR action.** `amend ADR-020` (§6 filter + vocabulary). ADR-002/019 `none`.

## NW-59 — Ask never dead-ends (abstain recovery)

`ReplyBody.tsx:75` renders abstain as `.abstain-block` only; `replyTypes.ts:50`
says "abstain/error never carry actions" — but R-ASK-07 forbad the block as the
**only** UX. Ruling: an `abstain` carries a **recovery action** that unblocks
*this* failure.

1. **Type contract:** `AbstainReply` (`replyTypes.ts:63-66`) gains
   `actions: readonly ReplyAction[]` (empty = true "cannot determine", but a
   recovery is the default). Rewrite `:50`.
2. **Render:** `ReplyBody` abstain branch (`:72-77`) renders
   `<ActionRow actions={reply.actions} />` after the block when non-empty.
   Actions are **secondary** (never primary).
3. **Recovery set** (copy mine; targets are existing routes): no validated
   contract → "Go to Documents" (`/documents`); unknown supplier → "Upload a
   contract" (`/documents`) / "Compare in Quote check" (`/quotes`); benchmark →
   "Open Quote check" (`/quotes`). Legal is a `refusal`, not `abstain` — no action.
   Specific recovery maps to the reply's own reason, never a generic pillar.

**Anchors.** `replyTypes.ts:50,63-66`; `ReplyBody.tsx:72-77`.

**ADR action.** `amend ADR-020` (abstain recovery). `AbstainReply` wire mapping
is sw/client's; the "must carry an action" rule + copy is mine. `ADR-019 none`.

**Design ref.** `screens-v2.md` §2; "abstain block only" divergence named
(requirements win, R-ASK-07).

`AppShell.tsx:82` always renders `GlobalAskBar`; on `/ask` the composer
duplicates it. Ruling: suppress the bar on `/ask` and `/ask/:conversationId`,
