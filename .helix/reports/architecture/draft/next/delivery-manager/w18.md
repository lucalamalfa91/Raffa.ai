**Decision.** Operator confirmation walk, not a code change. Confirm on both
`raffa-dev` and `raffa-demo` (HCP UI, not inferable from a green run) that the
two container apps carry the w15-era keys and that the workload identity holds
its Foundry RBAC. This is a gate/runbook step, never a workflow edit.

**Key set to confirm per environment (API):**
- `Invitations__Mail__Enabled`, `Invitations__Mail__SenderAddress`,

  `Invitations__AcceptUrlBase`, `Invitations__GuestProvisioning__Enabled`,
  `Invitations__GuestProvisioning__TenantId`
- `AzureAd__Authority`, `AzureAd__TenantId`, `AzureAd__ClientId`,
  `AzureAd__Audience`

**Foundry RBAC to confirm**: the shared workload identity already holds
`Cognitive Services User` + `Cognitive Services OpenAI User` on the shared
`aisvc-raffa` account (ADR-005 w15 §5 / ADR-008). Confirm it is still there —
not a new grant, a verification that no regression dropped it.

**Why this is a proof, not a deploy.** `backend.yml` deploys
`az containerapp update --image` only (`backend.yml:196-208`). Env vars arrive
only via Terraform + an HCP apply a human confirms. A green CI run proves
neither the apply landed nor the keys exist. Confirm in HCP UI, not from logs.

**ADR action.** `none — operator confirmation; ADR-005/ADR-016 already cover
the apply path and the promotion gate`. The confirmation joins the w18 final
integration acceptance walk (it needs no dedicated task; ride final
integration, ADR-014 w17 clause 7's "runbook steps ride final integration").

**Consequences for decomposition.** No `depends_on` edge, no writer. Add a line
to `reports/audit/w18-hitl.md` (operator prerequisite + the confirmed checklist)
and record the result in `docs/waves/w18-acceptance.md`'s known-gaps as an

## NW-41 — prove deployed API serves market_record rows

**Decision.** The code is landed (PARTIAL per intake: `market.sql:44`,
`MarketRecordQueryService` registered `ServiceCollectionExtensions.cs:131`,
`GET /api/market/records/{id}` `MarketEndpointExtensions.cs:40`). The residual
is a **dev walk** proving a seeded row is actually served over HTTPS. This is a
runbook step, not a workflow or code change.

**The proof, split (matching ADR-005 §14's static/dynamic discipline):**
1. **Static** — the `Market` schema is applied (`market.sql` in both
   `backend.yml:277-285` and `:309-317` arrays, "in lockstep" `:274-275`), the
   `market_record` / `market_embedding` tables exist.
2. **Dynamic** — seed a row (or confirm the seed workflow
   `seed-market-intelligence.yml` ran), then `curl` the deployed `dev` endpoint
   (exact status + body), signing in as a tenant-scoped identity. Prove the
   served row, not just the endpoint existing.

**One identity wrinkle worth recording.** The endpoint is tenant-scoped
(ADR-009/ADR-011), so the curl needs a real JWT, not a bare `az` call. The walk
names the exact test account and route from `dev`'s fixture. Never assert
"served" from a Swagger or a missing-tenant 4xx.

**ADR action.** `none — dev walk; ADR-024 owns the market data source and
ADR-001 the V1 market scope. The proof is an acceptance step, not a decision.`

**Consequences.** No `depends_on`, no writer. Join NW-40's final-integration
row; record the pass/fail result in the acceptance doc.

## NW-50 — day1.spec.ts red vs V2 shell (reconcile, no unexplained skip)

**Decision.** `web/e2e/day1.spec.ts` is pre-V2 (Ask is home; `.ask-message`,
`.abstain-block`, the ten screens of `screens.md`). The ship is now V2 Shell
(routes `/workspace/*`, `/contracts`, `/savings`, `/quotes`, `/ask`; Ask no
longer home). The spec is therefore **red by construction**: it drives a world
(`sign in → pick workspace → invite → upload → review → 360 → Ask`) whose markup
and route order partially moved. Reconcile the spec, or re-scope it, with a
**named, evidenced decision** — never a bare `test.skip` and never a silent
delete.

**What is NOT decided here: wiring Playwright into CI.** ADR-016 w15 clause 10
and w16 clause "still W18" said the runner is joint (delivery + security). This
council does **not** wire `web.yml` to run Playwright this wave: it would be a
CI-YAML change (a real `.github/workflows/**` diff) in a wave whose set is
zero, and it needs a non-interactive Entra credential (identity-plane change,
security-architect's, not in w18's roster for NW-50). **No task minutes a
runner.** The deliverables are: the spec reconciled + the honest disposition
recorded.

**Three dispositions, pick the evidenced one (client-architect reconciles the
web facts):**
1. **Re-scope to V2 Shell** — rewrite the walk to land on Home → Portfolio →
   Contract 360 → Ask, matching the V2 route map (`ia-v2.md`). Preferred if the
   e2e harness still compiles against current markup.
2. **Demote to a documented gap** — mark it not-CI and move the walk to a
   later wave, with the reason written in `web/README.md`'s e2e section, not a
   `skip`.
3. **Split** — keep Day-1 as a `demo`-only manual walk (it is already
   `RAFFA_E2E_BASE_URL`-gated and CI-less), and let `v2.spec.ts` / the
   w17-e2e specs carry the V2 assertions.

**ADR action.** `none — reconciliation + record. ADR-012 owns the e2e harness
and ADR-016 the "browser test ≠ CI gate" rule (clause 9).` The decision row is
`none — walk/sweep` in kind, but the disposition must be **written** (in the
acceptance doc and/or `web/README.md`), not implied.

**Consequences.** No `depends_on`, no writer, no workflow diff. The reconciled
spec (if any) is written by client-architect's side of the reconciliation; this
seat owns the **ordering** (run it in final integration, not CI) and the
**CI-non-wiring** ruling.
