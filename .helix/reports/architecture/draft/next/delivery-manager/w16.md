## NW-31 — the reprocess workflow (`.github/workflows/reprocess-tenant-documents.yml`)

This is the one wave allowed to open that file (ADR-016 w15 clause 21).

### D1 — OQ-w16-004 answered: **neither option**, because the premise is wrong

The assumption in force says the ADR-027 re-enqueue path "needs no new identity,
no secret and no Terraform". **Refuted on this tree.** Both Service Bus roles are
granted to the *container-apps workload identity only*, topic-scoped
(`infra/modules/servicebus/main.tf:73-74,91-92`; `variables.tf:27-28` states it as
a rule). CI logs in as `raffa-sp-<env>` (`reprocess-tenant-documents.yml:124-129`
→ `./.github/actions/azure-login`), which holds **neither** role. So:

- **runner-side publish** ⇒ a new `azurerm_role_assignment` ⇒ Terraform ⇒
  cloud-architect active + an infra PR before the wave PR (ADR-014 w15 clause 5);
- **API call with a token** ⇒ an app role on `azuread_application.api` + an
  app-only token + a membership answer (ADR-025) ⇒ security-architect active, and
  it diffs the one resource ADR-015 w15 clause 25 pins hardest (`~` never `-/+`,
  `identifier_uris` no diff — the SPA binds to that string, `web.yml:204-205`).

ADR-027 `:198`'s "reprocess collapses into re-enqueue" is a statement about the
**handler**, not about an operator path: the re-enqueue runs inside a process that
already holds the workload identity. **There is no zero-cost repair.**

→ **Ruling: w16 buys CI no new credential** (ADR-016 clause 10 — a wave does not
acquire a CI capability as a side effect). **cloud-architect stays uninvolved →
`PASS`; the wave's Azure/Terraform delta is zero.**

### D2 — the file is broken on **three** axes; "give it a token" repairs one

1. **Auth** — 401 at the first call (`GET /api/documents`, `:194-234`) since NW-05.
   Confirmed; its own 403 diagnostic (`:274`) is unreachable dead code.
2. **Contract** — the POST loop accepts **only `200`** and reads
   `.pagesParsed` / `.chunksIndexed` (`:260-270`). Since NW-27 the endpoint returns
   **202** with `{documentId, extractionJobId, processingStatus}`
   (`DocumentsEndpointExtensions.cs:523-535`, ADR-027 §D1). Every document would
   fall to the `*)` branch → `FAILED` → `exit 1`.
3. **Timing** — the `%PDF` assertion (`:345-366`) runs immediately after the POST
   loop, but the work is now asynchronous. It would assert on a corpus **mid-
   reprocess**: a false red, or a false green on a tenant nothing has processed yet.

A credential fixes (1) and leaves a job that fails differently, or passes wrongly.
**The repair is a rewrite, and the rewrite is what does not fit this wave.**

### D3 — disposition: keep the credential-free half, delete the rest

`reprocess-tenant-documents.yml` **deleted**; `verify-tenant-corpus.yml` **added**
(one writer, one task).

- **Keep** (works today, needs no API auth): OIDC login `:124-129`, RG resolution,

  assertion (R-DOC-07 AC-1) `:345-366`, the supplier report (R-SUP-03) `:374-387`,
  the summary. **Keep `environment:` `:104`** — it still reads a Key Vault secret,
  so `demo`'s required reviewers still gate it.
- **Delete**: the three API steps (`:178-290`), all four `X-*` headers,
  `OPERATOR_USER_ID` `:95` (an audit actor for rows it no longer writes — also
  keeps NW-32's grep sweep clean), the dead `workflow_call` trigger `:68-78`
  (**zero callers** — `backfill-workspace-membership.yml:168,221` cite it in
  comments only), the stale "Role posture" header `:38-48`.
- **Add**: psql enumeration of the tenant's documents + `processing_status`, and a
  named **worklist** of documents still needing a reprocess. The job reports; it
  does not mutate.
- **Fallback the table may take in one line**: keep the filename and rewrite the
  body. Cheaper diff, but a file named `reprocess-*` that never reprocesses is a
  new instance of the stale-record defect NW-31 exists to delete.

### D4 — acceptance still closes, because the product path is live

`useDocumentsList.ts:240` → `apiClient.reprocessDocument` → `POST /api/documents/
{id}/reprocess` → `ResolveTenantAsync` → `IsAdminAsync` → **202**
(`DocumentsEndpointExtensions.cs:492-535`). Membership-derived Admin, real token,
today. **Proposed A16-3 wording** (the workflow half only): *no `X-Role` /
`X-Workspace-Role` / `X-User-Id` remains in `.github/`; an Admin resubmits a

**bulk** job.

### D5 — the bulk job is designed here and scheduled to **W17**

Recorded so W17 does not re-derive it. Shape: an operator console
(`backend/scripts` or a `Raffa.Tools` project) referencing
`Raffa.Documents.Contracts` + `Raffa.Messaging`, calling
`DocumentReprocessService.ReprocessAsync` per document — so the `extraction_job`
row, the `document.reprocessed` audit row and ADR-027 §D5's replace step stay the
product's own code, never re-implemented in bash (the deleted file's header
`:14-32` already argues this). Postgres from the Key Vault secret CI reads today;
publish under `DefaultAzureCredential` with **one** topic-scoped `Azure Service
Bus Data Sender` for `raffa-sp-<env>` — preferred over the API-token shape because
it never touches `azuread_application.api` and never makes a service principal a
workspace Admin. **Open for W17**: security-architect on whether a CI principal
may hold a send right at all and what actor an operator console writes (NW-32);
cloud-architect on the module change.

### D6 — three shortcuts pre-empted

Named so they are refused rather than discovered (ADR-016's clause-2 style):

- **a Service Bus SAS key in Key Vault** — forbidden by the module's own rule
  (`servicebus/variables.tf:28`: "never a shared access key, never a Key Vault
  secret") and ADR-011;
- **re-adding any `X-*` identity header** — nothing reads them after NW-05; it
  only turns 401 into a different 401;
- **inserting `extraction_job` rows with `status='Queued'` via psql** — the
  dangerous one, because rows change and it *looks* like it worked. **Nothing
  sweeps them**: ADR-027 §D3 deliberately has no sweeper, the Worker is
  message-driven, and a row with no message is a permanently-`Queued` job the UI
  renders as "processing" forever.

## Ordering constraints for the decomposition (`depends_on` hints)

The intake's six constraints (§5 "Order constraints") stand. Mine add to them:

1. **The workflow task is independent**: it deletes API calls, so it depends on
   nothing and nothing depends on it. Give it **its own task**, so a phase boundary
   never blocks it and **exactly one task in the wave claims `.github/workflows/**`**
   (`check_single_writer.py`).
2. **contract-A `depends_on` both NW-08 backend and NW-31's capabilities-reader
   deletion** — otherwise the contract says `X-Role` is gone (`raffa-api.v1.json:5239`)
   while `CapabilitiesEndpointExtensions.cs:54,77-80` still reads it. A phase
   boundary between them is the safe form.
3. **contract-A and contract-B in different phases** (ADR-012 §3; `schema.ts` is
   regenerated wholesale). Two contract tasks, never six.
4. **Theme A strictly before theme B** — NW-32 edits the five services NW-11/12/21
   modify; sharing a phase fails `check_single_writer.py`.
5. **NW-12 and NW-21 must not share a phase** while both claim
   `NegotiationsEndpointExtensions.cs`; NW-12 first (it renders what NW-21 links).
6. **W16-01 last, first to cut**; no task already opens `Raffa.Worker` this wave,
   so it is its own task.
7. **The final-integration task is alone in the last phase.**
8. **No task opens `infra/`, and no task opens a workflow other than the NW-31
   pair.** The baseline's pending Terraform apply (D12) is an **operator** action,
   not a wave task — a decomposer that sees `infra/` churn in the recent log must
   not mint a task for it. `git diff origin/main..HEAD -- infra` stays empty.
