### 1 · Capabilities — the header goes and the server-side role filter goes with it

`GET /api/capabilities` **stops reading a client-asserted role and stops
filtering**: it returns **every catalog row, each carrying its own `roleGate`**
(ADR-024 w16 clause 2; ADR-022 w16 clause 2). Delete
`RoleHeaderName` (`backend/src/Raffa.Api/CapabilitiesEndpointExtensions.cs:54`),
`CallerIsAdmin` (`:77-80`) and the catalog gate (`:64-67`).

**Why the filter is dropped rather than moved to membership** (security's *named
acceptable alternative*, not its primary form): `GetCapabilities(HttpRequest)`
(`:62`) takes **no tenant and no caller**, `CapabilityCatalog.All` is **static
and tenant-free**, the client sends no `X-Tenant-Id` on this call, and
`ICallerContext`'s ladder **cannot express "200 without a token"** — so
membership-gating would `400` every call from a shell component rendered on every
screen. **Not acceptable, then or now: keeping any client-asserted role.**

> **S16-6a — the rule the alternative now depends on.** The catalog is henceforth
> served **whole to an unauthenticated caller**. That is acceptable **only**
> because it discloses *which admin features exist and nothing else*. Therefore
> `CapabilityCatalog` carries **no tenant data, no per-tenant entry, no count, no
> workspace name and nothing caller-derived** — and this task **proves it with an
> identical-response test**: the same response for (i) no token, (ii) a non-Admin
> token, (iii) an Admin token. *That property used to be protected by accident,
> because the gate hid half the list; from w16 it is protected by the rule.*

`roleGate` **stays on the wire as a label**. It is **presentation, never
authorization** (S16-11): every action behind an admin-gated entry is enforced
server-side by membership on its own endpoint. Hiding an admin-gated suggestion
chip from a non-Admin is client work deferred to **W17** (OQ-w16-sa-02), and
**it must never be re-described as a security fix**.

### 3 · The workflow — `reprocess-tenant-documents.yml` is DELETED, `verify-tenant-corpus.yml` is ADDED

**OQ-w16-004 is answered "neither option", and the premise under it was false.**
The assumption in force held that ADR-027's re-enqueue "needs no new identity, no
secret and no Terraform". Refuted from the Terraform: both Service Bus roles are
granted to the **container-apps workload identity only**, topic-scoped
(`infra/modules/servicebus/main.tf:71-102`), the module takes **no CI input**, and
CI's `raffa-sp-<env>` holds exactly one Terraform-granted role — `Key Vault
Secrets User` (`infra/modules/keyvault/main.tf:66-75`). **There is no zero-cost
repair, and w16 buys CI no new credential.** The wave's cloud delta is zero
**because the API steps are deleted, not because re-enqueue was free**.

**The file is broken on three axes and a credential repairs only one**:
(1) **auth** — 401 at the first API call since NW-05, making its own 403
diagnostic at `:274` unreachable dead code; (2) **contract** — the POST loop
accepts only `200` and reads `.pagesParsed`/`.chunksIndexed` (`:260-270`) while
the endpoint now returns **202**, so every document falls to `*)` → `FAILED` →
`exit 1`; (3) **timing** — the `%PDF` assertion races work that is now
asynchronous. *A token fixes (1) and leaves a job that fails differently or
passes wrongly.*
