# task-01-upload-returns-when-stored — The endpoint returns when stored; the aggregates stop guessing

## Coding objective

Cut the AI pipeline out of the upload request and let the API tell every screen
what is ready. In `DocumentsEndpointExtensions.cs` the upload handler keeps the
format/size checks it already runs in-request and then returns **201 as soon as
the blob and the rows are durable** — `:265-273`'s
`await processingPipeline.ProcessAsync(...)` goes away, and so does the
content-refusal `422` at `:242-252`, because a content refusal is now a
**`Rejected` row** the Worker writes. `DocumentAdmissionGate` splits along the
same line. `POST /api/documents/{id}/reprocess` (`:85`) re-enqueues instead of
re-running `DocumentReprocessService` inline.

Then add the fields that stop four screens from inferring readiness:
`counts` on the documents list, `readiness` on `GET /api/contracts/{id}`, and
`processingDocumentCount` on `GET /api/contracts`. Publish all of it in
`web/openapi/raffa-api.v1.json`, regenerate the typed client, and add the
hand-written wrappers in `client.ts` — **inline shapes only**, no `$ref` and no
`oneOf` at any depth.

## Context the implementer needs

`Closes: NW-27 (endpoint and gate half), NW-61 (server half)`.

Decision rows: `reports/architecture/waves/w15.md` — **NW-27** (product-owner,
software-architect and ux-ui-designer cells) and **NW-61** (product-owner,
software-architect and client-architect cells).

- **Architecture decisions in force**: **ADR-027** §D1, §D6–§D9 and §C1, §C5,
  §C9; **ADR-024** w15 footer §1–§4; **ADR-012** w15 §9–§10; **ADR-026 §D2**;
  **ADR-001** w15 clauses 1–3.
- **`counts` is five overlapping projections, not a partition.** No sum holds —
  a test asserting `all = needsAttention + …` is wrong, not the endpoint. And
  `all − needsAttention` must **never** be rendered as *askable*: that is the
  document-level fifth definition of ready the table refused (ADR-027 §C9.1).
- **`readiness.stage` is nullable, so it must not carry an `enum`.** The
  generator checks `enum` before the nullable union, so a nullable enum loses
  its `null` (ADR-012 w15 §9). `readiness.state` is non-nullable and may.
- **Nested objects render correctly — the earlier claim that they render
  `unknown` is withdrawn.** `renderSchemaType` recurses
  (`web/scripts/generate-api-client.mjs:109-111`) and the contract already nests
  three deep; only `$ref` / `oneOf` render `unknown`. **Land `counts` and
  `readiness` inline, touch no generator, hand-write no DTO** — a hand-written
  DTO in `client.ts` is the one prohibition ADR-012 `:53` has held since it was
  accepted. The generator's own doc comment at `:98-106` still says "flat
  property maps only"; its next two lines falsify it, and w15 is the first wave
  to exercise the recursion.
- **The eighth contract site is invisible to the build.** Seven `processingStatus`
  sites are schema properties; the eighth is a **query parameter** the generator
  never parses, so a partial edit fails no build and no `tsc` check. The check
  is a grep, not a green build.
- **A refusal's reason is a code, never a sentence.** The API must not author
  user-facing prose — the screen picks the words (ADR-020 w15 §6). Today
  `uploadPipeline.ts:123` renders `result.error` straight to the user; that
  channel closes in `E16/F03/US01/T01`.
- **Do not touch**: `Program.cs` — no route is added, moved or removed this
  wave, and the transport registration was `E16/F02/US02/T01`'s in phase 2. Do
  not touch `web/src/routes/**` — the screens are `E16/F03/US01/T01` in phase 4.
  Do not touch the invitation surface of the contract — `identityProvisioned`,
  `deliveryOutcome` and the declared 502 are `E17/F02/US01/T01`'s in phase 4.
  Do not add a CHECK constraint or any DDL: `Rejected` is code-only.
