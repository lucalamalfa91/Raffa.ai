# task-01-theme-b-contract-and-client — Publish theme B's five paths and add the three wrappers

## Coding objective

Declare in `web/openapi/raffa-api.v1.json` the five contract deltas theme B's
backend tasks landed in earlier phases, regenerate the typed client, and add the
three `ApiClient` methods the web halves will call.

The five deltas:

1. **`GET /api/renewals/{id}/action`** — `200` with the persisted row
   (`contractId`, `owner`, `status`, `action`, `updatedAt`), `404` when none
   exists. `{id}` carries the meaning `E19/F01/US01/T01` confirmed against
   `backend/src/Raffa.Api/RenewalsEndpointExtensions.cs:353`; state it in the
   path's description rather than leaving a reader to guess.
2. **`GET /api/renewals`** — the row schema gains **`savedAction`** (nullable
   object). The existing `action` property is **unchanged**.
3. **`GET /api/quotes`** — the tenant-scoped list.
4. **`GET /api/quotes/{id}`** — the quote with its recorded negotiation outcomes
   embedded, newest first.
5. **`GET` and `PUT /api/contracts/{id}/negotiation-steps`** — the tick keys;
   `PUT` takes the whole set, an unknown step name is `400`.

Then `npm run generate:api` and add exactly three methods to
`web/src/api/client.ts`: **`getQuote`**, **`getNegotiationSteps`**,
**`putNegotiationSteps`** — each with a row in `web/tests/api/client.test.ts`.
`GET /api/renewals/{id}/action` and `GET /api/quotes` are published **unwrapped**,
and the omission is recorded in `info.description` beside the existing
`/api/insights/criticality` and `GET /api/contracts/{id}/strategy` entries, so it
reads as a decision and not an oversight. Re-export the generated row type for
the persisted renewal action from `client.ts`, so the four files that import only
the `TrackedRenewalAction` type have a generated replacement — **no hand-written
DTO**.
