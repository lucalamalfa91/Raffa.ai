# task-01-step-ticks-api — One tenant table for the four negotiation steps, and the two routes that read and write it

## Coding objective

Give Contract 360's negotiation tracker a server-side home. In
`backend/src/Raffa.Documents.Contracts`, add the entity
`ContractNegotiationStep` (subclassing `TenantScopedEntity`, mapped in
`DocumentsContractsDbContext`), its EF configuration, and **one** migration that
creates the table `contract_negotiation_step` **together with its RLS policy**.
Add `NegotiationStepService` (read the set, write the whole set) and register it
in `backend/src/Raffa.Documents.Contracts/Infrastructure/ServiceCollectionExtensions.cs`
alongside the module's other services. Then map
`GET /api/contracts/{id}/negotiation-steps` and
`PUT /api/contracts/{id}/negotiation-steps` in
`backend/src/Raffa.Api/ContractsEndpointExtensions.cs`, following
`GET /api/contracts/{id}/corrections` (`:66`, handler `:431-473`) **verbatim**:
`ICallerContext.ResolveTenantAsync` first (`:442-446`), non-GUID id → `400`
(`:451-454`), unknown contract → `404` (`:459-462`).

The `step` column stores the step's **name** as a closed enum, never an array
index and never the rendered label. The four accepted names come from the design
oracle. **The row's presence is the tick** — there is no `ticked` boolean, and an
untick deletes the row, which is what makes the whole-set `PUT` idempotent.

Finally, regenerate the checked-in script with
`dotnet ef migrations script --idempotent` so
`backend/src/Raffa.Documents.Contracts/Migrations/Scripts/documents-contracts.sql`
matches the model. **Never hand-edit that file.**

## Parent story AC covered

- AC-1 `GET /api/contracts/{id}/negotiation-steps` returns the ticked step keys; an untouched contract returns an empty set, not `404`.
- AC-2 `PUT` writes the whole set idempotently; a key absent from the body is unticked.
- AC-3 An unknown step name returns `400` and writes nothing.
- AC-4 Non-GUID id `400`; unknown contract `404`; no token `401`; non-member `404`.
- AC-5 A second tenant's ticks never appear.
- AC-6 The four accepted keys are exactly the four canonical names.
- AC-7 Ticks are per contract; contract Y is unaffected by contract X.

- **Architecture decisions in force**: **ADR-028 §D3** (module, routes, table,
  keys, the whole-set `PUT`); **ADR-003** w16 clause 1 (columns and the unique
  key; **no `ticked` boolean**); **ADR-009** w16 clause 2 (`ENABLE` + **`FORCE`**
  + a policy with **both `USING` and `WITH CHECK`**, in the table's own
  migration; branch **2a** — the entity must subclass `TenantScopedEntity` **in
  `DocumentsContractsDbContext`**, which is what makes the free CI branch
  available); **ADR-021** w16 (one regenerated script, byte-compared; **no
  `backend.yml` change**); **ADR-002** w16 clause 1 (`Raffa.Renewals` cannot own
  this — its allow-list is `[SharedKernel, Benchmark]`, enforced by
  `backend/tests/Raffa.ArchitectureTests/DependencyDirectionTests.cs`);
  **ADR-001** w16 clause 3 (four canonical steps, key not index, label
  client-side, per contract).
- **Design oracle and the anchor this task implements**:
  `inputs/design/prototypes/raffa-v2/screens-v2.md:106-108` — the four **named,
  ordered** steps of the tracker's "4-step checklist":
  **Notify · Request revised pricing · Counter with the market benchmark · Sign
  or send non-renewal notice**. These four names are the enum. A fifth is a
  product change, not an implementation detail.
- **Why not an index**: the client store is a positional, unnamed `boolean[4]`
  (`web/src/routes/contracts/contract360/negotiationStepsStore.ts:11,18,24,31`)
  and the rendered labels live in
  `web/src/routes/contracts/contract360/contract360ViewModel.ts:211-218` with
  **two of the four parameterized** (supplier name, cancellation deadline). An
  index key silently re-points every tick if a step is inserted; a stored label
  would freeze a fact that later changes.
- **The enum-as-string convention already in this codebase**:
  `backend/src/Raffa.Quotes/Domain/NegotiationOutcome.cs:112-116`
  (`LeversUsed`). Follow it; invent nothing.
- **The host needs no edit.** `MapContractsEndpoints()` is already called by the
  API host, and the module's services are already registered through
  `AddDocumentsContractsModule`, so both new routes and the new service arrive
  with no change to the host's startup file. ADR-028 reserved that file for this
  task; this task finds it does not need it, which is the cheaper outcome.
- **Do not touch**: `web/openapi/raffa-api.v1.json`, `web/src/api/client.ts` or
  `web/src/api/generated/schema.ts` — the contract publication is
  `E19/F06/US01/T01`, one phase later. Do not touch
  `.github/workflows/backend.yml`: the two script arrays at `:277-285` and
  `:309-317` list **modules**, and `Raffa.Documents.Contracts` is already in
  both, so a new migration inside it moves no CI YAML — **any `backend.yml` diff
  in this wave fails the final-integration check**. Do not touch any of the nine
  services `E18/F03/US02/T01` edits in this same phase.
